## 1. 한 줄 내러티브 (덱 전체를 꿰는 문장)

> "외근의 단절을 한 앱으로 잇겠다고 약속했고, **모바일 MVP를 넘어 웹까지** 닿았다. 그 과정에서 AI 보고서처럼 **데이터가 아니라고 말한 기능은 과감히 잘라**, 현장의 전·중·후가 그대로 구조화 보고서가 되고 모든 외근이 지도 위에 쌓이는 **더 단단한 제품**을 남겼다. 그리고 실증은 다음 방향까지 알려줬다 — **현장은 거점이 아니라 점(point) 자산으로 재정의돼야 한다.** 2학기엔 그 모델 위에 잘라둔 것들(EXIF·정밀좌표·AI)을 제대로 다시 세운다."

**톤**: "약속을 다 지켰다"(X) → "**만든 것만큼 잘라내는 판단도 실증의 일부**"(O). 기말 채점에서 후자가 훨씬 강하다.

## 2. 문제 정의 (Recap 슬라이드 소재)

현장 외근은 세 군데서 끊긴다:

| 단절 | 내용 |
|---|---|
| **수작업 보고** | 외근 후 보고서를 손으로 작성 (사진 + 위치 수기 입력) → 행정력 낭비 |
| **데이터 단절** | 비정형 문서(HWP) 방식 → 외근 데이터를 데이터 자산으로 활용 불가 |
| **흐름 파편화** | 경로 탐색·보고서 작성이 따로 놂 → 통합 플랫폼 부재, 업무 흐름 단절 |

→ **일가요: 외근의 한 흐름을 한 앱으로 통합.**

### ✅ 실제 구현 — 성과로 말해도 되는 것

| 기능 | 무엇이 되는가 (정확히) |
|---|---|
| **외근 풀 라이프사이클** | 현장 등록 → 외근 구성(현장 다중선택) → 진행(지도) → 체크인 → 종료 → 보고. 끊김 없는 한 동선. |
| **현장 등록 — 단일 화면** | **주소검색(도로명·지번·장소명 POI) + 현 위치 GPS 측위 + 핀 지도 드래그가 한 화면에서 실시간 연동** (입력하면 핀이 움직이고, 핀을 끌면 주소가 따라옴). 상세주소·분류·프로젝트 지정, 중복 주소 확인("그래도 등록"), 한국 영역 가드. 수정 화면도 동일 구조. |
| **빠른 촬영 (Quick Photo)** | 현장에서 버튼 한 번 → GPS 측위 → **최근접 현장 자동 매칭** → 사진 즉시 등록. 근처에 현장이 없으면 **촬영 좌표·사진을 그대로 들고 새 현장 등록으로 폴백**. "기록 마찰 최소화"의 대표 기능이자, 2학기 '점 자산' 모델의 예고편. |
| **방문 순서 자동정렬** | 외근 시작 전, 출발지 기준 **최근접 이웃(nearest-neighbor)** 으로 방문 순서 자동 정렬 + 거리·ETA 표시. 수동 재정렬 가능. |
| **active 외근** | 이 외근의 현장만 스코프된 지도 + **목적지 관리(도착 표시·건너뛰기·순서 변경·목적지 추가)**, 진행률 표시, 최적 순서 재추천, 길찾기(카카오 deep-link), 체크인·빠른 촬영 진입. |
| **체크인 / 방문결과 6종** | 체크인 시 방문 결과 상태 6종 기록: 완료·부재·거부·주소불명·재방문필요·기타. ('기타'는 사유 10자+ 필수) + 전·중·후 사진 슬롯. |
| **구조화 보고서 (마법사)** | **작성 마법사**: 제목+외근 선택 → 방문 현장별로 차례로 **전·중·후 사진+캡션** 작성 (방문 0건이면 직접 작성으로 폴백). 보고서 = 줄글 본문이 아니라 "현장 × 단계" 사진 구조(field_reports). 상세에서 **Word 문서 다운로드**. 수정·삭제. |
| **지도 대시보드** | 모든 현장을 지도에 축적. **표시 방식 3종: 마커 / 히트맵 / 단계구분도(시·군·구 채색)** + 시/군/구 경계선·메모/사진 핀 토글 + 기간 필터(전체·1·7·30일). 경계 지오메트리(~3MB)를 번들에 내장해 오프라인에서도 렌더. 목록 쪽은 검색 + 상태/기간/프로젝트/분류 필터. |
| **현장 직접 첨부** | 외근과 무관하게 현장 상세에서 텍스트 메모·사진을 바로 추가/삭제. 사진·메모는 지도에 핀으로도 노출. |

## 6. 두 개의 핵심 스토리 (깊게)

### 6-A. AI 보고서를 잘라낸 결정 (S11 — 발표의 클라이맥스)
- **시도**: AI 원클릭 보고서 생성 기능을 개발했다 (`POST /api/reports/generate`, 사진+메모로 보고서 초안 생성).
- **데이터**: QA에서 2건 실패(#14·#15) + 운영 환경에서 500 에러 반복.
- **구조적 사유**: 동시에 진행한 스키마 단순화(ERD v2)로 **보고서 '본문(content)' 이라는 개념 자체가 사라짐.** AI가 채울 칸이 없어짐.
- **결정(2026-05-31)**: 기능을 **완전 제거**하고, 현장 사진을 **전·중·후 구조**로 묶는 방식으로 선회.
- **메시지**: "마법(AI 작문) 대신 구조." 만드는 것만큼 잘라내는 판단도 실증의 일부.
- (발표 중 질문 대비 근거: 코드 주석에 제거 결정·사유가 명시돼 있음. 슬라이드엔 경로 노출 X, 구두로만.)

### 6-B. 현장 재정의 — 거점에서 점 자산으로 (S13 — 2학기 헤드라인)
- **현 모델**: 지금 '현장(field)'은 **거점("시청")** — 도로명주소로 식별되고, 여러 번 방문하며, 상태 생애주기를 갖는 목적지. 좌표는 주소를 지오코딩한 대표점 1개.
- **실증으로 얻은 통찰**: 현장은 사실 **점(point) 자산("가로수 한 그루")** 이어야 한다 — 정밀 좌표가 1차 정체성이고, 현장에 서서 사진/GPS로 즉석 생성하는 대상.
- **방향**: **프로젝트를 거점으로 승격, 현장을 점으로** 재정의(ERD v3). 프로젝트는 이미 1학기에 그 부모 슬롯으로 추가해 둠.
- **왜 1학기엔 안 했나**: 재정의는 이름 바꾸기가 아니라 ERD v3급(주소 필수 계약 완화 + 프로젝트에 위치 승격 + 외근·보고서 재앵커링). ERD v2 단순화 직후라 의도적으로 2학기로 미룸.
- **연결**: 이 모델 위에서야 **EXIF/촬영 GPS 기반 현장 생성**이 장식이 아니라 "생성의 본래 방식"으로 제값을 한다. (지도 대시보드는 이미 점 뷰라 그대로 재사용)

## 7.5 동봉 다이어그램 (IAD.drawio · ERD.drawio) 해설

> 두 파일 모두 drawio XML — 내용을 직접 파싱해 도식을 재구성해도 되고, 사용자가 drawio에서 PNG로 내보내 슬라이드에 넣어도 된다. **2026-06-06 MVP 동결 시점의 as-built 기준**으로 최신화된 상태라 §3과 1:1 정합.

### IAD (Information Architecture Diagram) — 화면 구조
- **메인 = 4-탭**: 외근 / 현장 / 보고서 / 내 정보 (+ 진입부에 자동 로그인 분기 → 로그인/회원가입).
- 외근 탭: 목록→상세(방문 상세·결과 정정), "진행 중 외근?" 분기 → 시작 마법사(현장 선택→순서 결정→최적 순서 추천) 또는 진행 중 화면(목적지 관리 4동작·길찾기·종료·방문 0건 확인).
- 현장 탭: 지도 대시보드(표시 방식 3종·표시 여부·필터) / 목록(검색·필터) / 상세(수정·삭제·직접 첨부·체크인·길찾기) / 단일 화면 등록(주소검색·현 위치·핀 지도·중복 확인·한국 영역 거부) / 빠른 촬영(매칭 분기).
- 점선 화살표 = cross-tab 진입 3개: 진행 중 외근→체크인, 진행 중 외근→빠른 촬영, 빠른 촬영 폴백→현장 등록(좌표·사진 이관).
- **슬라이드 활용**: S4 라이프사이클 도식의 근거 / 부록(Appendix)에 전체 IA 한 장.

### ERD (Entity-Relationship Diagram) — 데이터 모델 (ERD v2)
- 테이블 11개: users · locations · projects · trips · fields(허브) · visits · destinations* · memos · field_photos · field_categories · reports · field_reports.
- 구조 요지: **fields가 허브** — 위치(locations 1:1), 프로젝트(선택 소속), 메모/사진/분류가 현장 직속(방문이 아니라). 보고서 본문 = field_reports(현장×전·중·후 사진). Crow's Foot 표기, 깊이(Depth) 레인으로 부모→자식 배치.
- ***destinations는 점선** = 기능은 완료, 저장은 클라이언트(백엔드 영속화 예정) — §3 🟡과 동일 사실. 슬라이드에 ERD를 쓸 경우 이 점선 의미를 잘못 옮기지 말 것.
- **슬라이드 활용**: S12 "ERD v2 단순화" before/after의 after 근거 / S13 현장 재정의(ERD v3 예고)의 출발점 도식.

## 8. 데모 영상 샷 리스트 (모바일 화면 녹화, 동선 통제)

1. 로그인 → 외근 탭
2. 현장 등록(단일 화면) — 주소검색 → 핀 지도 좌표 확인 → 분류·프로젝트 (부산 실주소 사용)

6. 빠른 촬영 — 버튼 한 번 → 최근접 현장 매칭 → 사진 등록 (짧고 임팩트 큼)
