2. **발표 형식**: 총 **~15분**, 데모는 **사전 녹화 영상**(별도 제공 예정)을 포함.
3. **BASE.pptx 자산**: 캔버스 크기(16:9 대형) 유지. 기존에 디자인된 **타이틀 슬라이드**(큰 "일가요" 히어로 타이포)와 **Milestone 타임라인**(3~12월 로드맵)은 재제작하지 말고 재활용 (날짜·상태 표시 정도만 갱신).
4. **미정 정보**: 발표 날짜 · 팀원별 역할/기여 → 사용자가 별도 제공 (임의로 채우지 말 것).

이 외의 모든 것 — 슬라이드 수, 순서, 시간 배분, 어떤 소재를 살리고 버릴지, 도식화 방식, 레이아웃 — 은 Desktop이 판단한다.

## 2. 제품 개요 · 문제 정의 (사실)

- **제품**: **일가요** — 지도 기반 외근 도우미. 현장 방문 업무자(단일 사용자 역할: 필드 워커)용 모바일·웹 앱.
- **팀**: 내 친구 지성 팀 (과목: 실증적SW개발프로젝트, 기말 발표).
- **풀려는 문제** — 현장 외근은 세 군데서 끊긴다:

| 단절 | 내용 |
|---|---|
| 수작업 보고 | 외근 후 보고서를 손으로 작성 (사진 + 위치 수기 입력) → 행정력 낭비 |
| 데이터 단절 | 비정형 문서(HWP) 방식 → 외근 데이터를 데이터 자산으로 활용 불가 |
| 흐름 파편화 | 경로 탐색·보고서 작성이 따로 놂 → 통합 플랫폼 부재, 업무 흐름 단절 |

→ 일가요의 제안: **외근의 한 흐름(등록→이동→기록→보고)을 한 앱으로 통합.**

## 3. 팀이 전하고 싶은 메시지 (소재 — 활용 여부·방식은 재량)

> "외근의 단절을 한 앱으로 잇겠다고 약속했고, 모바일 MVP를 넘어 웹까지 닿았다. 그 과정에서 AI 보고서처럼 데이터가 아니라고 말한 기능은 과감히 잘라, 현장의 전·중·후가 그대로 구조화 보고서가 되고 모든 외근이 지도 위에 쌓이는 더 단단한 제품을 남겼다. 그리고 실증은 다음 방향까지 알려줬다 — 현장은 거점이 아니라 점(point) 자산으로 재정의돼야 한다. 2학기엔 그 모델 위에 잘라둔 것들(EXIF·정밀좌표·AI)을 제대로 다시 세운다."

- 팀이 선호하는 톤: "약속을 다 지켰다"(X) → "**만든 것만큼 잘라내는 판단도 실증의 일부**"(O).
- 팀이 생각하는 두 개의 하이라이트 후보: ① AI 보고서를 잘라낸 결정(§5-A) ② 2학기 현장 재정의(§5-B). 강조 여부·배치는 재량.

## 5. 깊은 이야기 소재 3건 (쓸지 말지·어디 둘지는 재량)

### 5-A. AI 보고서를 잘라낸 결정
- **시도**: AI 원클릭 보고서 생성 기능을 개발했다 (`POST /api/reports/generate`, 사진+메모로 보고서 초안 생성).
- **데이터**: QA에서 2건 실패(#14·#15) + 운영 환경에서 500 에러 반복.
- **구조적 사유**: 동시에 진행한 스키마 단순화(ERD v2)로 **보고서 '본문(content)' 이라는 개념 자체가 사라짐.** AI가 채울 칸이 없어짐.
- **결정(2026-05-31)**: 기능을 **완전 제거**하고, 현장 사진을 **전·중·후 구조**로 묶는 방식으로 선회.
- **메시지**: "마법(AI 작문) 대신 구조." 만드는 것만큼 잘라내는 판단도 실증의 일부.
- (질문 대비 근거: 코드 주석에 제거 결정·사유가 명시돼 있음. 자료엔 경로 노출 X, 구두로만.)

### 5-B. 현장 재정의 — 거점에서 점 자산으로 (2학기 방향)
- **현 모델**: 지금 '현장(field)'은 **거점("시청")** — 도로명주소로 식별되고, 여러 번 방문하며, 상태 생애주기를 갖는 목적지. 좌표는 주소를 지오코딩한 대표점 1개.
- **실증으로 얻은 통찰**: 현장은 사실 **점(point) 자산("가로수 한 그루")** 이어야 한다 — 정밀 좌표가 1차 정체성이고, 현장에 서서 사진/GPS로 즉석 생성하는 대상.
- **방향**: **프로젝트를 거점으로 승격, 현장을 점으로** 재정의(ERD v3). 프로젝트는 이미 1학기에 그 부모 슬롯으로 추가해 둠.
- **왜 1학기엔 안 했나**: 재정의는 이름 바꾸기가 아니라 ERD v3급(주소 필수 계약 완화 + 프로젝트에 위치 승격 + 외근·보고서 재앵커링). ERD v2 단순화 직후라 의도적으로 2학기로 미룸.
- **연결**: 이 모델 위에서야 **EXIF/촬영 GPS 기반 현장 생성**이 장식이 아니라 "생성의 본래 방식"으로 제값을 한다. (지도 대시보드는 이미 점 뷰라 그대로 재사용. 빠른 촬영이 이 모델의 예고편.)

### 5-C. 기술 난제 (구두 디테일 + Q&A 백업)
- **① 웹+모바일 듀얼 타깃**: 한 코드베이스가 세 런타임(iOS·Android·Web)에서 돌며 갈라지는 지점을 명시적으로 분기 — 사진 업로드 FormData 직렬화(웹 Blob vs 네이티브 uri), 카카오 지도 주입(웹 iframe vs 네이티브 WebView), 보안 저장소(SecureStore vs localStorage 계열). "되게 만든" 게 아니라 분기 지점을 좁게 격리한 것이 포인트.
- **② JWT refresh 회전 + 멀티탭 레이스 복구**: refresh 토큰이 1회용으로 회전하는데 웹 멀티탭이 동시에 갱신을 치면 한쪽이 무효 토큰을 쥐는 레이스 — 세션 가드로 복구 경로를 만들어 해소.
- **③ 실전 디버깅 사례 (자료보다 Q&A용)**: 신규 아키텍처(Fabric)에서 로그인 직후 앱이 무음 종료되던 크래시(같은 틱 setState+navigate 배치 충돌)와, 바텀시트 목록이 끝까지 스크롤 안 되던 버그(라이브러리 높이 주입 누락)를 **가설이 아니라 기기 계측(console 수치 실측)으로** 잡아낸 사례. "실증적" 과목명과 결이 맞는 이야기.

### 그 외 회고 소재 (짧은 것)
- ERD v2 단순화 — 음성메모·공유링크·오프라인 등 YAGNI 제거로 스키마가 가벼워짐.

## 7. 동봉 자료 해설 (무엇이 들어 있는지 — 활용 방식은 재량)

### IAD.drawio — 화면 구조 (Information Architecture)
> drawio XML — 직접 파싱해 도식을 재구성해도 되고, 사용자가 PNG로 내보내 줄 수도 있다. 2026-06-06 as-built 기준이라 §4와 1:1 정합.

- **메인 = 4-탭**: 외근 / 현장 / 보고서 / 내 정보 (+ 진입부에 자동 로그인 분기 → 로그인/회원가입).
- **지도 대시보드는 메인 직속 공유 레이어** — 특정 탭 소속이 아니라 **모든 탭 화면의 지도 배경**(바텀시트 뒤). 표시 방식 3종·경계/핀 토글·기간 필터를 어느 탭에서나 쓸 수 있고, 화면별로는 표시할 현장 스코프만 다름. "현장 탭의 기능"으로 좁혀 말하면 부정확.
- 외근 탭: 목록→상세(방문 상세·결과 정정), "진행 중 외근?" 분기 → 시작 마법사(현장 선택→순서 결정→최적 순서 추천) 또는 진행 중 화면(목적지 관리 4동작·길찾기·종료·방문 0건 확인).
- 현장 탭: 목록(검색·필터) / 상세(수정·삭제·직접 첨부·체크인·길찾기) / 단일 화면 등록(주소검색·현 위치·핀 지도·중복 확인·한국 영역 거부) / 빠른 촬영(매칭 분기).
- 점선 화살표 = cross-tab 진입 3개: 진행 중 외근→체크인, 진행 중 외근→빠른 촬영, 빠른 촬영 폴백→현장 등록(좌표·사진 이관).

### ERD.drawio — 데이터 모델 (ERD v2)
- 테이블 11개 + 점선 1개: users · locations · projects · trips · fields(허브) · visits · memos · field_photos · field_categories · reports · field_reports + **destinations***(점선).
- 구조 요지: **fields가 허브** — 위치(locations 1:1), 프로젝트(선택 소속), 메모/사진/분류가 현장 직속(방문이 아니라). 보고서 본문 = field_reports(현장×전·중·후 사진). Crow's Foot 표기, 깊이(Depth) 레인으로 부모→자식 배치.
- ***destinations는 점선** = 기능은 완료, 저장은 클라이언트(백엔드 영속화 예정) — §4 🟡과 동일 사실. ERD를 인용할 경우 이 점선 의미를 잘못 옮기지 말 것. visits·field_photos 옆의 주황 주석 2개도 같은 "백엔드 대기" 표기다.
- 5-B(현장 재정의)의 출발점 도식이기도 하다 (ERD v3 예고용으로 인용 가능).

## 8. 데모 영상 (사용자가 녹화 예정 — 계획된 동선)

> 아직 미녹화. 아래 동선으로 녹화될 예정이므로, 영상이 커버할 내용을 참고용으로 공유한다 (상세: `DEMO_CAPTURE_GUIDE.md`). 데모 데이터는 부산 실주소 기준.

1. 로그인 → 외근 탭
2. 현장 등록(단일 화면) — 주소검색 → 핀 지도 좌표 확인 → 분류·프로젝트
3. 외근 시작 — 현장 2곳 선택 → 방문 순서 자동정렬 → 시작
4. active 외근 — 스코프 지도 마커 + 목적지 도착 표시 + 길찾기 진입
5. 체크인 — 전·중·후 사진 + 방문결과 상태 선택
6. 빠른 촬영 — 버튼 한 번 → 최근접 현장 매칭 → 사진 등록
7. 외근 종료 → 보고서 마법사 — 현장별 전·중·후 카드 완성 → Word 다운로드
8. 지도 대시보드 — 마커→히트맵→단계구분도 전환 + 기간 필터
