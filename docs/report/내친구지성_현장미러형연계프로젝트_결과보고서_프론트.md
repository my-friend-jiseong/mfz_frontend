## 1. 과제 개요

### (1) 프로젝트 명

**일가요** — 지도 기반 외근 도우미 (모바일·웹 앱)

### (2) 프로젝트 목적

현장 방문 업무(외근)는 세 군데에서 끊긴다.

| 단절 | 내용 |
|---|---|
| 수작업 보고 | 외근 후 사진·위치를 손으로 옮겨 보고서를 작성 → 행정력 낭비 |
| 데이터 단절 | 비정형 문서(HWP) 방식이라 외근 데이터를 자산으로 재활용 불가 |
| 흐름 파편화 | 경로 탐색과 보고서 작성이 따로 놀아 통합 플랫폼 부재 |

일가요는 **외근의 한 흐름(등록 → 이동 → 기록 → 보고)을 하나의 앱으로 통합**하는 것을 목적으로 한다. 현장의 전·중·후가 그대로 구조화 보고서가 되고, 모든 외근이 지도 위에 데이터로 축적되어 다음 의사결정의 근거가 되게 하는 것이 핵심 지향이다.

## 2. 과제 수행 과정

### (1) 설계 및 계획

**제품 구조(IA) 설계** — 메인을 **4-탭(외근·현장·보고서·내 정보) + 인증(로그인·회원가입)**으로 잡고, 지도 대시보드를 특정 탭이 아니라 **모든 탭 화면이 공유하는 지도 배경 레이어**(바텀시트 뒤)로 설계했다. 화면별로는 표시할 현장의 스코프만 달라진다.

**핵심 플로우 설계 결정 — 단일 화면 실시간 연동**: 현장 등록을 여러 단계로 나누지 않고, **주소 검색·현 위치(GPS)·핀 지도가 한 화면에서 실시간으로 맞물리는 단일 화면**으로 설계했다. 입력하면 핀이 움직이고, 핀을 끌면 주소가 따라오는 구조다. 검색창은 순수 검색용으로 두고, 진실의 출처는 핀이 가리키는 현장 카드로 단일화했다.

**디자인 시스템**: Pretendard 폰트와 토큰 기반 시스템을 세우고, 상태 표현은 **색만으로 정보를 전달하지 않도록 색 + 형상 + 라벨 3중 인코딩**으로 설계해 접근성을 확보했다.

**데이터 모델(ERD)**: 백엔드와 공동으로 설계하되, 개발 과정에서 음성메모·공유링크·오프라인 등 불필요한 항목을 걷어낸 단순화(ERD v2)를 거쳤다. fields(현장)를 허브로 두고 위치·프로젝트·메모·사진·분류가 현장에 직접 매달리는 구조다. (스키마 상세는 백엔드 작성)

### (2) 구현 내용

**① 외근 풀 라이프사이클** — 현장 등록 → 외근 구성(현장 다중선택) → 진행(지도) → 체크인 → 종료 → 보고로 이어지는 끊김 없는 한 동선을 구현했다.

**② 현장 등록 — 단일 화면 통합** — 주소 검색(도로명·지번·장소명 POI) + 현 위치 GPS 측위 + 핀 지도 드래그가 한 화면에서 실시간 연동된다. 상세주소·분류·프로젝트 지정, 중복 주소 확인("그래도 등록"), 한국 영역 가드를 포함하며, 수정 화면도 동일 구조로 통일했다.

**③ 빠른 촬영(Quick Photo)** — 현장에서 버튼 한 번으로 GPS 측위 후 **최근접 현장을 자동 매칭**해 사진을 즉시 등록한다. 근처에 현장이 없으면 촬영 좌표·사진을 그대로 들고 새 현장 등록으로 폴백한다. 기록 마찰을 최소화하는 대표 기능이다.

**④ 방문 순서 자동정렬** — 외근 시작 전 출발지 기준 **최근접 이웃(nearest-neighbor) 휴리스틱**으로 방문 순서를 자동 정렬하고 거리·ETA를 표시한다. 수동 재정렬도 가능하다.

**⑤ 진행 중(active) 외근** — 해당 외근의 현장만 스코프된 지도 위에서 목적지 관리(도착 표시·건너뛰기·순서 변경·목적지 추가), 진행률 표시, 최적 순서 재추천, 길찾기(카카오 deep-link), 체크인·빠른 촬영 진입을 제공한다.

**⑥ 체크인 / 방문결과 6종** — 체크인 시 방문 결과를 6종(완료·부재·거부·주소불명·재방문필요·기타)으로 기록하고('기타'는 사유 10자 이상 필수), 전·중·후 사진 슬롯을 제공한다.

**⑦ 구조화 보고서(작성 마법사)** — 보고서를 줄글 본문이 아니라 "현장 × 단계(전·중·후) 사진" 구조로 정의했다. 작성 마법사가 제목·외근 선택 후 방문 현장별로 전·중·후 사진과 캡션을 차례로 작성하게 하고(방문 0건이면 직접 작성으로 폴백), 상세 화면에서 **Word 문서로 다운로드**할 수 있다.

**⑧ 지도 대시보드** — 모든 현장을 지도에 축적하며 **표시 방식 3종(마커 / 히트맵 / 단계구분도)**을 제공한다. 히트맵은 밀도 추정(KDE) 캔버스 방식으로 전면 개편하고 실제 색 척도와 일치하는 범례·줌 연동 반경을 더했으며, 단계구분도는 시·군·구를 절대 건수 구간으로 채색한다. 행정구역 경계 지오메트리(약 3MB)를 앱 번들에 내장해 **오프라인에서도 렌더**된다. 메모/사진 핀 토글과 기간 필터(전체·1·7·30일)도 포함한다.

**⑨ 현장 직접 첨부** — 외근과 무관하게 현장 상세에서 텍스트 메모·사진을 바로 추가·삭제할 수 있고, 이는 지도에 핀으로도 노출된다.

**⑩ 웹 + 모바일 듀얼 타깃** — RN/Expo 한 코드베이스로 iOS·Android·Web을 동시 지원한다. 세 런타임이 갈라지는 지점(사진 업로드 FormData 직렬화, 카카오 지도 주입, 보안 저장소)을 명시적으로 좁게 격리했다.

**⑪ 인증** — JWT + refresh 토큰 회전 + bcrypt. refresh 토큰이 1회용으로 회전하는 구조에서 웹 멀티탭이 동시에 갱신을 치는 레이스를 세션 가드로 복구한다.

> 백엔드 영속화/엔드포인트를 기다리는 일부 항목(외근 계획 destinations 영속화, 사진 단계 메타 컬럼 등)은 **프론트 UI·로직은 완성되고 영속화만 대기** 중인 상태다. 상세는 백엔드 작성.

### (3) 테스트 및 검증

**기기 실측 디버깅** — 가설이 아니라 실기기 계측(console 수치 실측)으로 버그를 잡는 방식을 적용했다.

- **로그인 직후 무음 종료 크래시** — 신규 아키텍처(Fabric)에서 같은 틱에 setState와 화면 전환이 배치 충돌하던 것이 원인. 전환 이중 처리를 제거해 해소.
- **바텀시트 목록 스크롤 끊김** — 라이브러리 시트 높이 미적용과 목록 1페이지 절단 두 원인을 실측으로 분리해 모두 수정.
- 그 외 앱 지도 백지(지도 등록 도메인 지정), 사진 빈 칸, 방문 수 0건 표시, 외근 중 지도가 목적지로 끌려가던 문제 수정.

**단위 테스트** — 빠른 촬영의 최근접 현장 매칭 로직에 단위 테스트를 작성했다.

**통합 시나리오 회귀 검증** — 통합 시나리오 회귀 검증 스크립트를 정식화해 주요 동선을 반복 검증했다. (API 단위·통합 테스트는 백엔드 작성)

**QA 환류** — 운영에서 발견된 버그를 QA 시나리오로 환류하는 사이클을 운영했다.

### (2) 기대효과 및 향후 계획

**기대효과** — 외근의 전·중·후가 그대로 구조화 보고서가 되어 수작업 보고를 없애고, 모든 외근이 지도에 데이터로 쌓여 행정 데이터를 자산화한다. 등록·이동·기록·보고가 한 앱에서 이어져 업무 흐름의 단절을 해소한다.

**수행 과정의 판단 — "만든 것만큼 잘라내는 판단도 실증의 일부"** — 개발 도중 AI 원클릭 보고서 생성 기능을 만들었으나, QA 실패와 운영 오류가 반복되고 스키마 단순화로 보고서 '본문' 개념 자체가 사라지면서 **기능을 완전히 제거**하고 현장 사진의 전·중·후 구조 보고서로 선회했다. "마법(AI 작문) 대신 구조"라는 결정이며, 실증을 통해 무엇을 버려야 하는지까지 확인한 사례다.

| 02 | 보고서 포맷 확장 | PDF 우선(백엔드 요청 등재) → 실수요 확인 후 HWPX(공공 XML 표준). Word는 1학기 완료 |

| 04 | 엑셀 현장 입출력 | 템플릿 업로드로 현장 일괄 등록(지오코딩 배치) + 필터 반영 xlsx 내보내기 |

**피드백 및 수정사항** — 단계로 나뉘어 있던 현장 등록을 단일 화면 실시간 연동으로 전환한 것, 절대 건수 기반 단계구분도와 KDE 히트맵으로 지도를 전면 개편한 것, 보고서를 단계별 작성 마법사로 정식화한 것이 검증·피드백을 거쳐 확정된 주요 수정사항이다. (백엔드 측 피드백·수정사항은 백엔드 작성)

### (3) 활동사항

본 과제 수행과 관련한 학술대회·경진대회 등 외부 참여실적은 없음. 과제 수행 활동으로 기말 발표(시연 영상·화면 캡처 자료 포함)와 Android 스토어 출시 준비를 진행함.
