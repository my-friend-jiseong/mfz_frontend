## 판정: **승인 불가 (Not Approved)** — Blocker 7건

렌더링은 정확하고 정렬도 맞고 색도 안 부딪힌다. 그런데 **결정되지 않은 것들이 남아 있다.**

> 1. 흰 카드 균일 나열 → 위반 (현장 탭)
> 2. 숫자를 라벨과 같은 크기로 → 위반 (외근 탭)
> 3. 제목 없이 리스트로 시작하는 화면 → 준위반 (외근 탭 focal 소멸)
> 4. 다크 모드 → 준수 ✅

# 전역 — 탭별로 들어가기 전에

## G1 · 세 목록 탭이 구조적으로 구분되지 않는다 `Blocker`

**무엇이 defaulted 됐나**
외근·현장·보고서 세 탭이 **완전히 동일한 골격**을 반복한다.

```
지도 스트립(210px) → 시트 핸들 → h1 제목 → 검색창 → 필터칩 행 → 균일 카드 리스트
```

탭 간 차이는 필터칩 개수뿐이다 (현장 4개 / 외근 2개 / 보고서 1개).

**왜 generic하게 읽히나**
squint test 실패. 스크린샷에서 제목 글자를 지우면 **어느 탭인지 구분할 방법이 없다.**
하단 탭바의 파란 아이콘 하나가 유일한 단서다.

이게 특히 비싼 이유는 Direction이 "계측기"이기 때문이다. 계측기는 **게이지마다 생김새가 다르다** —
속도계와 연료계를 같은 모양으로 만들지 않는다. 세 탭이 같은 폼이면 사용자는 매번 제목을 *읽어서*
자기 위치를 확인해야 한다. 이동 중·장갑 낀 손·흔들리는 버스라는 이 앱의 전제에서 가장 비싼 비용이다.

**크래프트된 결정**
탭마다 상단 블록의 **형태 자체**를 다르게 정한다. 검색+칩 3종 세트를 모든 탭에 기계적으로 얹지 않는다.

| 탭 | 지배하는 형상 | focal |
|---|---|---|
| 현장 | 지도 우세 — 내 위치 중심 + 근접순 리스트 | 다음 목적지까지 거리 |
| 외근 | 타임라인/게이지 — 오늘·이번 주 진행 | 방문/계획 비율 |
| 보고서 | 문서 목록 — 검색이 1급 | 작성 건수 |

## G2 · 강령 3 위반 — 탭 루트 목록에 loading / error 상태가 없다 `Blocker`

**코드 검증 결과**

| 화면 | empty | loading | error |
|---|---|---|---|
| `fields/index.tsx` | ✅ EmptyState | ❌ | ❌ |
| `trips/index.tsx` | ✅ EmptyState | ❌ | ❌ |
| `reports/index.tsx` | ✅ EmptyState | ❌ | ❌ |

- `LoadingState` / `Skeleton` 컴포넌트는 **존재하지만** 상세·편집 화면에서만 쓰이고 탭 루트엔 0건
- `ErrorState`는 **컴포넌트 자체가 없다** (`src/components/`엔 `EmptyState.tsx`만 존재)

강령 3은 "데이터 화면은 loading / empty / error **반드시** 처리"인데 3개 중 1개만 충족한다.

**왜 사용자에게 비싼가**
야외 = LTE 불안정. 이 앱이 **가장 자주 만날 상태가 "느림"과 "실패"**인데 둘 다 화면이 없다.
지금 구조에선 서버가 죽어서 배열이 비어도 `EmptyState`가 뜬다 →
사용자는 **"서버 오류"를 "현장이 하나도 없음"으로 오독**한다. 이건 미관 문제가 아니라 오정보다.

**크래프트된 결정**
`ErrorState` 신설 — 재시도 버튼 + 오프라인/서버오류 구분. 목록 초기 로드엔 Skeleton.
**empty와 error는 절대 같은 화면으로 처리하지 않는다.**

## G3 · 지도가 죽은 영역 — 상시 210px을 점유하면서 아무것도 계측하지 않는다 `Blocker`

**현상**
모든 탭 상단에 동일한 지도 스트립이 상시 노출. 시트가 ~90%를 덮어 실효 노출은 얇은 띠.
마커도, 내 위치도, 경로도 읽히지 않는다. 검색바 하나만 떠 있다.

**왜 문제인가**
Direction의 핵심 동사가 **"다음 목적지를 찾아** 방문 결과를 남긴다"이다.
그 동사의 앞쪽 절반을 담당하는 유일한 UI가 **장식으로 전락**했다.
세로 공간 9%(2400px 중 210px)를 상시 소비하면서 정보량이 0이다.

**크래프트된 결정**
둘 중 하나로 결정한다 — 지금처럼 어중간하게 두지 않는다.

- **(A) 승격** — 현장 탭에서만 지도를 1급으로. 시트 기본 snap을 55%로 낮추고 내 위치 기준 근접 정렬
- **(B) 회수** — 목록 탭에선 지도 스트립 제거. 대신 "다음 목적지까지 N분" 계측 띠로 대체

# 현장 탭

## F1 · 거부 기본값 1번 정면 위반 — 흰 카드 균일 나열 `Blocker`

**현상**
카드 4장이 크기·간격·내부 레이아웃·배지 위치까지 전부 동일하다. 좌측 4px 컬러바만 다르다.
문서는 **"카드 크기·간격을 균일하게 두지 않는다"**고 명시했는데 현재 구현이 정확히 그 형태다.

**왜 generic하게 읽히나**
문서가 요구한 건 "**상태가 먼저 읽히는 목록**"이다. 지금은 **'흰 카드 덩어리'가 먼저 읽히고**
배지는 그다음에 읽힌다. 정보 순서가 뒤집혀 있다.

**크래프트된 결정**
같은 리스트 안에서 tier를 나눈다. 조치 전 = 승격(큰 카드, 진한 표면, 거리 표시),
조치 완료 = 축약행으로 강등(1줄, 무채색). 스캔하는 눈이 **할 일만** 잡히게 한다.

## F2 · 목록 카드에 숫자가 0개 — 계측기인데 계측값이 없다 `Blocker`

**현상**
카드 내용: 이름 / 주소 / 프로젝트 / 태그 / 상태배지 — **전부 텍스트, 숫자 0개.**

**왜 비싼가**
걷고 있는 점검 담당자에게 가장 비싼 정보는 **거리 또는 도보 소요시간**이다. 그게 없다.
Direction은 "focal element는 거의 항상 숫자"인데, 사용자가 가장 오래 머무는 목록 본문에 숫자가 없다.
현재 이 화면에서 유일한 숫자는 상단 요약의 145 하나뿐이다.

**크래프트된 결정**
카드 우측에 `metricSm`으로 거리(1.2km) 또는 도보 분. **정렬 기본값을 근접순으로.**

## F3 · 요약 블록의 세 숫자가 같은 층위를 두고 싸운다 `Should-fix`

"조치 전 **145**"는 `metric`+warning, "조치 중 145"·"조치 완료 143"은 caption 범례다.
문제는 **조치 전과 조치 중이 같은 값 145**인데 크기가 3단계 차이나서 순간 오독을 부른다는 것.

→ focal이 "조치 전" 하나라면 나머지 둘은 **숫자를 빼고 비율 바로만** 표현. 세 숫자를 나란히 두려면 같은 tier로.

## F4 · 필터칩 4개가 상시 펼쳐져 세로 예산을 먹는다 `Should-fix`

조치상태/프로젝트/카테고리/방문일이 **선택 여부와 무관하게** 항상 같은 자리를 차지한다(약 80px).
활성 필터가 하나도 없을 때도 마찬가지다.

→ 미선택 시 "필터" 단일 칩으로 접고, **선택된 것만** 값 칩으로 펼친다.

# 외근 탭

## T1 · 강령 8 위반 — 진행 숫자가 라벨과 같은 크기 `Blocker`

**현상**
"방문 3 / 계획 3곳", "43분", "01:01 시작" — 전부 body/caption 크기.
외근 카드에서 **유일한 계측값인 방문/계획이** 진행바 옆 작은 회색 텍스트로 밀려 있다.

문서: *"focal 숫자는 `metric`/`metricSm`, 라벨보다 **두 단계 위**"*

**크래프트된 결정**
`방문 3/3`을 `metricSm`으로 승격, "곳" 라벨은 `caption`+`textMuted`로 강등.
카드를 스캔할 때 **숫자가 먼저 눈에 들어오게.**

## T2 · 빈 주에는 화면의 focal이 통째로 소멸한다 `Should-fix`

코드상 `trips/index.tsx`에 `metricSm` 3개짜리 주간 통계 블록이 있으나,
실기기에선 **"이번 주 외근 없음" 한 줄로 대체**돼 화면을 지배하는 숫자가 사라진다.

결과적으로 거부 기본값 3번(focal 부재)에 준하는 상태가 된다.
→ 빈 주에도 게이지 형태를 유지(0/0)하거나, 지난 주 실적으로 대체해 **계측면을 비우지 않는다.**

## T3 · 배지와 진행바가 다른 이야기를 한다 `Note`

"진행중 화면 검증 / 방문 0 / 계획 3곳" 카드 — 배지는 초록 **완료**인데 진행바는 0%(연회색 미착수).
사용자는 어느 쪽을 믿어야 하는지 모른다.

# 보고서 탭

## R1 · focal 숫자 0건 `Should-fix`

`metric` variant 사용 0건(코드 검증). 그룹 헤더의 "방문 0건"이 유일한 수치인데 caption이다.
문서 목록이라 숫자 지배가 덜 필요한 건 맞지만, **화면에 focal이 없어도 된다는 뜻은 아니다.**

→ 그룹 헤더 방문 건수를 `metricSm`으로, 또는 상단에 "이번 달 작성 N건" 요약 게이지.

## R2 · "수정됨" 배지가 전부에 붙어 신호가 아니라 배경이 됐다 `Should-fix`

화면의 카드 **6개 전부**에 "수정됨"이 붙어 있다. 전부에 붙으면 정보가 아니다.
강령 2의 3중 인코딩 배지 어휘를 **소모만 하고 변별력은 0**이다.

→ 최근 수정(24시간 내)만 표시하거나, 배지를 없애고 타임스탬프에 통합.

## R3 · "외근 정보 미로드"는 사용자 언어가 아니다 `Note`

시스템 용어가 그대로 노출됐다. 사용자는 이게 **오류인지 정상 분류인지 알 수 없다.**
→ 정상 분류면 "외근에 연결되지 않은 보고서". 진짜 로드 실패면 G2의 error 상태로 처리.

# 내 정보 탭

## P1 · "문의하기" 라벨이 2줄로 깨진다 `Should-fix`

이메일 주소가 길어 라벨 열이 압축되며 "문의 / 하기"로 줄바꿈된다.
→ 이메일을 두 번째 줄(서브텍스트)로 내리고 라벨은 한 줄 유지.

## P2 · 회원 탈퇴가 스크롤 경계에 반쯤 잘려 있다 `Note`

파괴적 액션이 화면 밖으로 나가 있다. `dangerGhost` 규칙은 지켰으나 **배치가 위험**하다.
→ 분리된 섹션 하단에 충분한 여백 확보.

## P3 · 이 탭만 h1 제목이 없다 `Note`

다른 3탭은 제목으로 시작하는데 여기만 아바타로 시작한다.
아바타가 focal 역할을 하므로 거부 3번 위반은 아니지만 **일관성에 균열**이 있다.

# 현장 상세

## D1 · 강령 1 위반 — 동일 무게 CTA 2개 `Blocker`

**현상**
`길찾기`와 `수정`이 **같은 크기·같은 outline·같은 색**으로 나란히 놓여 있다.

**왜 문제인가**
강령 1은 "1 화면 = 1 결정. CTA가 둘이면 **위계로 답한다**"이다.
Direction의 핵심 동사가 "다음 목적지를 **찾아**"인데, 그 동사를 담당하는 길찾기가 승격돼 있지 않다.
현장에 서 있는 사용자가 이 화면에서 누를 확률은 길찾기가 압도적으로 높다.

**크래프트된 결정**
길찾기 = primary solid(full width 또는 2/3), 수정 = ghost 또는 아이콘 버튼으로 강등.

## D2 · 이 화면에도 focal 숫자가 없다 `Should-fix`

"메모 (1)", "방문 이력 (0)" 카운트가 섹션 라벨 안에 caption으로 묻혀 있다.
계측기 관점의 focal 후보: **현재 위치로부터의 거리**, **마지막 방문 경과일**.
→ 상단 배지 아래에 거리/경과 게이지 한 줄.

## D3 · 비활성 "추가" 버튼이 활성처럼 보인다 `Note`

비활성 상태가 primary 연한 파랑이라 활성/비활성 구분이 순간 모호하다.
(실제로 이번 테스트에서 리뷰어가 오독했다.)
→ 비활성은 채도를 빼고 `surface` 계열로.
