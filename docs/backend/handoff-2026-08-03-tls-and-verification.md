## 1. 🔴 운영 TLS 인증서가 만료됐다 — 앱이 서버에 붙지 못한다

**다른 모든 항목보다 앞선다.** 배포된 기능이 몇 개든 앱이 서버에 닿지 못하면 의미가 없다.

### 실측 (2026-08-03 19:57 KST)

```
Subject:   CN=ilgayo.co.kr
Issuer:    CN=E8, O=Let's Encrypt, C=US
NotBefore: 2026-05-05 06:39:16
NotAfter:  2026-08-03 06:39:15   ← 약 13시간 전 만료
```

| 확인 | 결과 |
|---|---|
| `curl https://ilgayo.co.kr/api-docs.json` | **실패** — `SEC_E_CERT_EXPIRED` |
| `curl -k` (검증 우회) | **200** — 서버·애플리케이션 자체는 정상 가동 중 |

서비스가 죽은 게 아니라 **TLS 신뢰만 끊겼다.** Let's Encrypt 자동 갱신이 실패한 상태다.

### 영향

- **앱에는 우회 수단이 없다.** RN/Expo 의 fetch 는 OS 트러스트 스토어를 쓰고, 프로덕션
  빌드에 인증서 검증 예외를 넣는 선택지는 없다(넣어서도 안 된다). **로그인부터 전부 실패한다.**
- Play 심사가 정책 링크(`/terms`·`/privacy`)를 열면 브라우저 경고를 만난다 — **항목 3 과 직접 부딪친다.**
- 프론트 웹 검증 환경도 같은 이유로 막혀 있다(아래 「프론트 현황」).

### ✅ 원인 확정 (서버 SSH 진단 완료 — 추측이 아니다)

**"갱신이 실패했다" 가 아니라, 이 인증서는 애초에 자동 갱신될 수 없는 방식으로 발급됐다.**

`/etc/letsencrypt/renewal/ilgayo.co.kr.conf` 가 답이다:

```
pref_challs = dns-01,
authenticator = manual
```

certbot 은 `--manual` 로 발급된 인증서를 **`--manual-auth-hook` 없이는 비대화식으로 갱신하지
않는다** — 사람 입력이 필요하므로 매번 건너뛴다.

| 확인 | 결과 | 의미 |
|---|---|---|
| `certbot.timer` | enabled·active, **9시간 전 실행됨** | 타이머는 정상. 여기가 문제가 아니다 |
| `live/fullchain.pem` | → `archive/…/fullchain**1**.pem` | **2세대가 없다.** 5/4 이후 갱신 성공 0회 |
| `live/` mtime | `May 4 22:37` | 그날 이후 갱신된 적 없음 |
| 디스크 | 10% | 무관 |

**타이머는 90일 내내 돌면서 매번 조용히 건너뛰었다. 만료는 사고가 아니라 예정된 결과였다.**

### 왜 manual/DNS-01 이었나 — 되돌릴 수 없는 제약이 있다

**80 포트가 외부에 열려 있지 않다.** 외부에서 `59.21.223.137:80` 은 connection refused 이고,
`mfz-nginx` 컨테이너는 호스트 **28080** → 컨테이너 80 으로 매핑돼 있다. HTTP-01 은 80 포트를
요구하므로 **처음부터 쓸 수 없었고**, 그래서 DNS-01 수동 발급을 택한 것으로 보인다. nginx conf 에도
`.well-known/acme-challenge` location 이 없다(전부 백엔드로 프록시).

### ⚠️ 갱신만으로는 부족하다 — 컨테이너 reload 가 필요하다

TLS 종단은 호스트 nginx(둘 다 `inactive`)가 아니라 **Docker 컨테이너 `mfz-nginx`** 이고,
`/etc/letsencrypt` 를 **read-only 마운트**해 기동 시점에 인증서를 읽는다(4일째 가동 중).
호스트에서 갱신해도 **컨테이너를 reload 하지 않으면 만료본을 계속 서빙한다.**

### 요청

**① 즉시 복구** — 대화식이다(DNS TXT 추가 필요). 서버 접근·DNS 패널 권한이 있는 사람이 해야 한다.

```bash
sudo certbot certonly --manual --preferred-challenges dns \
  -d ilgayo.co.kr -d www.ilgayo.co.kr
# 안내되는 TXT 레코드를 가비아 DNS 관리에 추가 → 전파 대기 → Enter
docker exec mfz-nginx nginx -s reload      # ★ 빼면 만료본을 계속 서빙한다
```

**② 재발 방지 — 이게 본론이다.** ① 만 하면 11월에 똑같이 만료된다.
DNS 는 **가비아**(`ns.gabia.co.kr`)이고 서버에 certbot DNS 플러그인은 없다.

| 안 | 방법 | 평가 |
|---|---|---|
| **A** | 네임서버를 **Cloudflare** 로 옮기고 `certbot-dns-cloudflare` (등록기관은 가비아 유지) | **권장** — 완전 자동, 무료, 공식 플러그인. 80 포트 제약과 무관 |
| B | 가비아 DNS API 를 호출하는 `--manual-auth-hook` 자작 | 공식 플러그인이 없어 직접 짜야 하고 API 변경에 취약 |
| C | 80 포트 개방 + webroot HTTP-01 | 공유기·ISP 정책에 막힐 수 있고 nginx location 추가도 필요 |

어느 안이든 **deploy hook 을 반드시 건다**: `--deploy-hook "docker exec mfz-nginx nginx -s reload"`

**③ 만료 임박 알림** — 이번 장애의 진짜 교훈은 **90일 동안 아무도 몰랐다**는 것이다.

```bash
0 9 * * * openssl s_client -connect ilgayo.co.kr:443 -servername ilgayo.co.kr </dev/null 2>/dev/null \
  | openssl x509 -noout -checkend 1209600 || echo "ilgayo.co.kr 인증서 14일 내 만료"
```

### 덤 — `mfz-studio` 컨테이너가 크래시 루프 중

같은 진단에서 발견. `Restarting (1)` 이 초 단위 반복이고 로그는 `prisma studio` **사용법 도움말**만
출력한다 — 인자 없이 기동돼 즉시 종료되는 상태다. 장애와 무관하고 급하지 않지만 4일째 초당
재시작 중이라 로그·CPU 를 계속 먹는다. 안 쓰는 컨테이너면 내리는 게 낫다.

### 발견 경위 (같이 남길 것)

2026-07-29 배치의 프론트 반영 여부를 확인하려고 OpenAPI 를 받으려다 TLS 단계에서 죽어 발견했다.
**기능 확인을 하러 갔다가 장애를 먼저 만난 셈**이다 — 정기 운영 헬스체크가 없다는 뜻이기도 하다.
모니터링을 붙일 계획이 있다면 이번이 근거다.

## 2. 🔴 signup 의 `agreedTerms` 는 버전값을 **검증하는가?** (답변 한 줄)

### 왜 묻는가

프론트는 `agreedTerms` 에 **그 시점에 실제로 서빙 중인 본문의 시행일**만 싣는다. 지금
`/terms`·`/privacy` 가 여전히 **`시행일: 2026-06-18`** 구 초안을 서빙하므로(2026-08-03 실측),
프론트가 보내는 값은 `{ service: "2026-06-18", privacy: "2026-06-18" }` 다. `location` 은
페이지가 없어(404) 아예 싣지 않는다.

이건 의도된 규칙이다 — **사용자는 아직 배포되지 않은 문서에 동의할 수 없다.** 앞선
`2026-08-03` 을 미리 적으면 사실이 아닌 동의 이력이 쌓이고, 그건 기록이 없는 것보다 나쁘다.

### 질문

`POST /auth/signup` 이 `agreedTerms` 의 버전값을 **현행 버전(`legalVersions.js` = `2026-08-03`)과
대조해 거절**하는가?

- `POST /api/me/legal/accept` 에는 `terms_version_invalid`(400) 가 문서화돼 있는데,
  signup 의 400 은 일반 "입력 검증 실패" 뿐이라 OpenAPI 만으로 판정이 안 된다.
- 무인증 프로브로 확인하려 했으나 `password_confirm_mismatch` 가 먼저 걸렸고,
  확정하려면 실계정 생성이 필요해 멈췄다.

### 왜 급한가

**검증한다면 지금 신규 가입이 전부 실패한다.** 그 경우 프론트가 항목 3 배포 전까지
`agreedTerms` 를 아예 빼야 하므로, 답이 오는 즉시 조치한다.

> 참고: 검증하지 않는 쪽이 낫다고 본다. 클라이언트가 **자기가 실제로 보여준 문서의 버전**을
> 기록하는 게 동의 이력의 목적이고, 서버가 현행 버전만 받으면 "구 문서를 본 사용자" 라는
> 사실 자체를 기록할 수 없게 된다. `needsReaccept` 가 이미 그 불일치를 표현하고 있다.

## 3. 🔴 `/location-terms` 는 여전히 404, 약관 본문은 구 초안 (§30-B)

2026-08-03 실측:

| 경로 | 상태 | 본문 시행일 |
|---|---|---|
| `/terms` | 200 | **2026-06-18** (구 초안) |
| `/privacy` | 200 | **2026-06-18** (구 초안) |
| `/location-terms` | **404** | — |

앞 핸드오프의 항목 2 그대로다. **약관 3종의 시행일이 `2026-08-03` 인데 오늘이 그날**이고,
서빙되는 본문은 여전히 6월 초안이다.

### 이것이 막고 있는 것 (연쇄)

1. 프론트는 `/location-terms` 가 404 인 동안 **위치정보 약관 메뉴를 노출하지 않는다**
   (`LOCATION_TERMS_AVAILABLE=false`). 심사 대상 앱에서 404 로 가는 정책 링크는 없느니만 못하다.
2. 그래서 `agreedTerms.location` 도 보내지 않는다 → 위치 동의 이력이 계속 비어 있다.
3. 서버 현행이 `2026-08-03` 이라 **`needsReaccept` 가 전 사용자에게 `true`** 다.
   프론트는 이 때문에 **재동의 배너를 일부러 붙이지 않았다** — 지금 붙이면 전원에게 뜨고,
   눌러도 사용자가 읽을 새 본문이 없다. **B 가 원인인 증상을 C 의 UI 로 덮지 않는다.**

즉 §30-C 는 배포됐지만 **§30-B 없이는 사용자에게 도달하지 못한다.** 본문이 오면
프론트는 `utils/contact.ts` 의 `LEGAL_DOCS` **한 곳**을 올리는 것으로 메뉴·동의 버전·배너가
한꺼번에 풀린다.

## 4. 🟢 2026-07-29 배치 — 프론트 대조 완료 (참고)

결과보고서의 「프론트 연동 체크리스트」에 대한 실측 답이다. **백엔드가 할 일은 없다.**

| **§30-A** `DELETE /api/me` | ✅ `/api/me` = get·patch·**delete** | ✅ 완료 | 선반영해 둔 계약(재인증 password·`{deleted:true}`·`current_password_invalid`)이 **그대로 맞았다**. 코드 변경 0 |
| **§30-C** `legal` · `/legal/accept` | ✅ 둘 다 있음 | ◑ 계약 계층만 | 배너 미배선 — 항목 3 참조 |

| **§19** export 에러 문구 | ✅ | — | 프론트는 자체 문구를 쓰므로 무관 |

### §26 은 문서 항목이 아니라 **실제로 죽어 있던 기능**이었다

설명을 붙여준 덕에 원인이 잡혔다. 프론트는 진행률 "방문 N / 계획 M곳" 의 **분모로
`siteCount` 를 쓰고 있었는데**, 그건 계획 수가 아니라 **들른 현장 수**라 정의상 항상
`siteCount ≤ visitCount` 다. 그래서 "분모가 방문 수보다 작으면 신뢰 불가" 가드가 **100%
발동**했고 — **진행률 바가 단 한 번도 그려지지 않고 있었다.** `destinationCount` 로 바꿔
해소했다.

> 이 항목의 교훈은 **필드 설명이 기능이라는 것**이다. `{"siteCount": {"type":"integer"}}`
> 한 줄에 설명이 없어서 프론트가 몇 달간 잘못 읽었다. 새 필드에는 세는 대상을 한 문장으로
> 적어주면 이런 종류가 사라진다.

### 덤 — 스펙에 없는 필드가 프론트 타입에 있었다

같은 대조에서 프론트의 `durationHHMM: string` 이 **존재하지 않는 필드**임이 드러났다
(백엔드는 목록·상세 모두 `durationMinutes: integer`). 소비처가 0곳이라 무증상이었지만
쓰는 순간 `undefined` 가 나오는 함정이라 정정했다. **백엔드 조치 불요** — 프론트 타입 오류였다.
