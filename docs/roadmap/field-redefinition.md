# 현장 재정의 — 거점에서 점(point) 자산으로 (ERD v3)

> **상태**: 검토 (2학기 헤드라인 — 2026-06-01 사용자 결정으로 1학기 포기·2학기 이월)
> **백로그**: 미등재 (ERD v3 확정 후 백엔드 협업 항목으로 분해 예정)

## 현 모델 → 목표 모델
- **현재**: 현장(field) = **거점**("시청") — 도로명주소로 식별, 여러 번 방문, 상태 생애주기. 좌표는 주소 지오코딩 대표점 1개.
- **목표**: 현장 = **점 자산**("가로수 한 그루") — 정밀 좌표가 1차 정체성. 현장에 서서 사진/GPS 로 즉석 생성하는 대상. **프로젝트를 거점으로 승격**하고 현장이 그 아래 점으로 소속.

## 왜 ERD v3급인가 (1학기에 안 한 이유)
- 주소 필수 계약 완화 (점은 동·호수가 없음 — §4 detailAddress 완화가 그 선행 신호)
- 프로젝트에 위치(거점 좌표) 승격
- 외근·보고서의 앵커를 점 기준으로 재정의
- ERD v2 단순화 직후라 연속 대수술을 피해 의도적으로 이월

## 이 모델이 열어주는 것
- **EXIF/촬영 GPS 기반 현장 생성**이 장식이 아니라 "생성의 본래 방식"이 됨 (1학기 빠른 촬영이 예고편 — 매칭·폴백 흐름 재사용)
- 지도 대시보드는 이미 점 뷰(마커·히트맵·단계구분도)라 그대로 재사용

## 미정 (명세화 필요)
- 기존 거점형 현장 데이터의 이관 규칙 (거점 1개 → 프로젝트 승격? 점 1개로 유지?)
- 점의 식별 UX (이름 없는 점을 목록에서 어떻게 부를지 — 좌표·사진 썸네일·순번?)
- 방문/체크인의 단위 (점 단위 체크인 vs 거점 단위 체크인 + 점 작업 기록)
