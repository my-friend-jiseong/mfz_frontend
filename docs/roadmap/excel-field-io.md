# 엑셀 현장 입출력 — 일괄 등록(import) · 내보내기(export)

> **상태**: 확정 (2026-06-06 사용자 결정 — 세부 검토 항목 하단)
> **백로그**: 미등재 (방식 확정 후 백엔드 항목 분해 예정)
> **배경**: 현장이 수십 곳 이상인 사용자는 한 건씩 등록하는 현재 흐름이 병목. 반대로 축적된 현장·방문 데이터를 조직 내부 문서/타 시스템으로 가져갈 출구도 없음.

## 1. 일괄 등록 (엑셀 → 현장)

### 흐름
1. 템플릿 다운로드 (열: 주소* · 상세주소 · 현장명 · 상태 · 프로젝트 · 분류(쉼표 구분) — 현행 단건 등록 입력과 1:1)
2. 작성한 xlsx 업로드 → 행 단위 파싱·검증 → **미리보기 표** (몇 행 등록·몇 행 오류)
3. 확정 → 일괄 생성 → 결과 리포트 (성공/실패 행 + 사유)

### 기술 검토
- **지오코딩 배치가 핵심 난점**: 주소→좌표 변환을 행마다 수행 — 카카오 지오코더 rate limit 고려해 순차+딜레이 또는 백엔드 배치. 실패 행(검색 0건)은 오류 리포트로.
- 단건 등록의 기존 검증 재사용: 한국 영역 가드 · 중복 주소 확인(일괄에서는 "중복 N건 — 그래도 등록/건너뛰기" 일괄 선택).
- 파싱 위치: 프론트(SheetJS 계열로 클라이언트 파싱 → 기존 `POST /api/fields` 반복 호출) vs 백엔드(multipart 업로드 → 서버 파싱·배치 생성). **대량(수백 행)이면 백엔드 배치가 정답** — 부분 실패 트랜잭션 정책도 서버가 가져야 함.

## 2. 내보내기 (현장 → 엑셀)

### 범위
- 현장 목록 xlsx: 주소 · 상세주소 · 상태 · 프로젝트 · 분류 · 좌표 · 최근 방문일 (+ 선택: 방문 이력 시트)
- 진입점: 현장 탭 목록 — **현재 적용된 필터 그대로** 내보내기 (검색·상태·기간·프로젝트·분류).

### 기술 검토
- 소량이면 프론트 단독 가능 (store 데이터 → xlsx 생성 → 웹 다운로드 / 네이티브 공유 시트). 방문 이력 포함 등 서버 데이터 조인이 필요하면 백엔드 export 엔드포인트.

## 미정 (명세화 필요)
- 일괄 등록 상한 (1회 몇 행까지) · 부분 실패 정책 (전체 롤백 vs 성공분 유지)
- 템플릿에 좌표 직접 입력 열을 둘지 (지오코딩 우회 — 측량 데이터 보유 사용자용)
- 내보내기에 방문·메모·사진 URL 포함 범위
