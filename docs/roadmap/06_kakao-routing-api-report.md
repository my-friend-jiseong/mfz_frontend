## 1. 결론 요약

1. 이 앱의 본질은 내비게이션이 아니라 **방문지 관리 도구**다. 실제 길 안내는 카카오맵·카카오내비 앱에 위임한다.
2. **앱 내부에서 그리는 경로는 자동차 하나뿐이다.** 대중교통·도보는 딥링크로 넘긴다. 이 결정 하나로 환승 타임라인 UI 전체와 가장 불안정한 API 의존성이 사라진다.
3. **사업자등록은 필요 없다.** 무료 쿼터 범위 내에서 개발자 계정의 첫 번째 앱으로 쓰면 결제 수단(비즈월렛) 연결이 요구되지 않는다.
4. 경로 API가 **두 개의 서로 다른 플랫폼**에 나뉘어 있다. 도메인도 쿼터도 다르다 (§5).
5. **동선 최적화는 완전탐색으로 충분하다.** 방문지 8곳 이하에서 TSP 휴리스틱은 불필요하다 (§8).

## 2. 확정된 API 범위

### 2.1 채택 — 이것만 구현한다

| # | API | 플랫폼 | 용도 |
|---|---|---|---|
| 1 | 지도 SDK | 카카오맵 | 지도 표시 (기구축) |
| 2 | 주소로 좌표 변환 | 카카오맵 REST | 방문지 주소 → 좌표 |
| 3 | 좌표로 주소 변환 | 카카오맵 REST | 방문 완료 체크 시 주소 자동 기록 |
| 4 | 자동차 길찾기 | 카카오모빌리티 | 앱 내부 경로 폴리라인 |
| 5 | 다중 목적지 길찾기 | 카카오모빌리티 | 동선 최적화용 비용 행렬 |
| 6 | 카카오맵 URL Scheme | 딥링크 | 대중교통·도보 안내, 실제 길 안내 |

3번(좌표로 주소 변환)은 선택이다. `fetch` 한 줄이라 복잡도가 사실상 0이면서 외근 기록 기능의 완성도를 올려준다.

### 2.2 제외 — 구현하지 않는다

| API | 제외 근거 |
|---|---|
| 대중교통 경로 조회 | 환승 타임라인 UI가 화면 하나만큼 추가된다. §10의 미해결 이슈 리스크. 딥링크로 대체 |
| 도보 경로 조회 | 대중교통과 함께 딥링크로 이관 |
| 자전거 경로 조회 | 공무원 외근에 자전거 시나리오 없음 |
| 다중 출발지 길찾기 | 다수 차량 배차용. 1인 외근과 무관 |
| 다중 경유지 길찾기 | 자동차 길찾기의 경유지 5개로 충분. 방문지가 6곳을 넘으면 그때 재검토 |
| 정적 지도 조회 | 지도 SDK가 일 30만 건인데 일 1,000건짜리로 썸네일을 만들 이유가 없음 |
| 좌표계 변환 | 카카오 API가 전부 WGS84. 외부 레거시 좌표계 데이터를 받지 않음 |
| 카테고리로 장소 검색 | 주변 시설 검색은 부가기능. 필요 시 딥링크 |
| 키워드로 장소 검색 | 방문지는 주소로 입력받는다. 주소 → 좌표 변환으로 충분 |
| 실시간 길안내 SDK (내장형) | 네이티브 전용이라 RN 브리지를 직접 작성해야 함. 투입 대비 효과 최악 |
| 미래 운행 정보 길찾기 | 출장 시각 예약 기능이 범위에 없음 |

## 3. 계정 및 권한 설정

### 3.1 절차

1. 카카오계정으로 [카카오디벨로퍼스](https://developers.kakao.com) 가입
2. 앱 생성 → REST API 키, 네이티브 앱 키 발급
3. **[앱] > [제품 설정] > [카카오맵] > [사용 설정]을 ON**
4. REST API 사용 시 REST API 키에 필요한 설정 등록
5. 지도 SDK 사용 시 플랫폼 키에 플랫폼 정보 등록
   - Web(JavaScript) SDK → JavaScript 키에 도메인 등록
   - Android/iOS SDK → 네이티브 앱 키에 앱 정보 등록

2026년 7월 21일 정책 변경으로 **별도 신청이나 관리자 심사 없이** 3번의 토글만으로 활성화된다. 그 이전 문서·블로그에 나오는 "추가 기능 신청 후 승인 대기" 절차는 더 이상 유효하지 않다.

### 3.2 반드시 지킬 것 — 앱은 하나만 만든다

무료 쿼터는 **앱 단위가 아니라 개발자 계정 기준 "첫 번째로 카카오맵 API를 활성화한 앱"에만** 주어진다.

- 팀원이 각자 계정으로 테스트 앱을 만드는 건 무방하다 (각자의 첫 번째 앱)
- 그러나 **한 계정에서 두 번째 앱을 활성화하면 그 앱은 즉시 유료 대상**이 되고 비즈월렛 연결을 요구받는다
- **팀 대표 계정 1개 → 앱 1개 → 키 공유** 구조로 가라. 개발/운영 환경을 앱으로 분리하지 마라

무료 쿼터가 적용된 앱은 앱 정보에 `카카오맵 무료 쿼터` 배지가 표시된다.

### 3.3 유료 전환 조건

- 개발자 계정 기준 첫 번째 활성화 앱이 아닌 앱에서 사용
- 앱 활성화 순서와 무관하게 무료 쿼터를 초과

졸업작품 규모에서는 둘 다 해당되지 않는다. 해당되게 만들지 마라.

## 5. 플랫폼 구분 — 헷갈리지 마라

카카오의 경로 API는 역사적 이유로 두 조직에 나뉘어 있다. 인증 키는 같은 REST API 키를 쓰지만 도메인, 문서, 쿼터 집계, 활성화 조건이 전부 다르다.

| | 카카오맵 | 카카오모빌리티 |
|---|---|---|
| 도메인 | `dapi.kakao.com` | `apis-navi.kakaomobility.com` |
| 문서 | developers.kakao.com | developers.kakaomobility.com |
| 이 프로젝트에서 담당 | 지오코딩, 지도 SDK | 자동차 경로, 다중 목적지 |
| 활성화 | [제품 설정] > [카카오맵] ON 필요 | 앱 생성만으로 가능 |
| 인증 헤더 | `Authorization: KakaoAK {REST_API_KEY}` | 동일 |

### 5.1 절대 쓰면 안 되는 엔드포인트

경로에 `/affiliate/`가 들어간 카카오모빌리티 엔드포인트는 **제휴 파트너 전용이며 사전 제휴 계약이 필요하다.** 계약 없이 호출하면 실패한다. 검색 결과 상단에 이 문서들이 먼저 뜨는 경우가 많으니 URL을 확인하라.

## 6. 엔드포인트 명세

### 6.1 공통 인증

```
Authorization: KakaoAK {REST_API_KEY}
```

지도 SDK에는 REST API 키를 쓰면 안 된다. 플랫폼별 지정된 키(JavaScript 키 / 네이티브 앱 키)를 써야 하며, 잘못 쓰면 에러가 난다.

### 6.2 자동차 길찾기 — 앱 내부 경로의 유일한 소스

```
GET https://apis-navi.kakaomobility.com/v1/directions
```

**제약 (공식 문서 확인됨)**: 하나의 출발지에서 하나의 목적지까지. **경유지 최대 5개.** 모든 경유지를 포함한 총 거리는 1,500km 미만.

| 파라미터 | 형식 | 비고 |
|---|---|---|
| `origin` | `경도,위도` | `angle` 추가 지정 가능 |
| `destination` | `경도,위도` | |
| `waypoints` | `경도,위도` 를 `\|`로 구분 | 최대 5개 |
| `priority` | `RECOMMEND` / `TIME` / `DISTANCE` | |
| `car_fuel` | `GASOLINE` 등 | 유류비 계산용 |
| `car_hipass` | `true` / `false` | |
| `alternatives` | `true` / `false` | 대안 경로 |
| `road_details` | `true` / `false` | |
| `summary` | `true` / `false` | true면 요약만 반환 |

응답 구조 (확인됨):

```json
{
  "trans_id": "...",
  "routes": [{
    "result_code": 0,
    "result_msg": "길찾기 성공",
    "summary": {
      "origin": { "name": "", "x": 127.107, "y": 37.402 },
      "destination": { "x": 127.109, "y": 37.394 },
      "waypoints": [{ "name": "", "x": 127.173, "y": 37.366 }],
      "priority": "RECOMMEND",
      "bound": { "min_x": 0, "min_y": 0, "max_x": 0, "max_y": 0 },
      "fare": { "taxi": 22200, "toll": 0 },
      "distance": 19032,
      "duration": 3494
    },
    "sections": [{
      "distance": 10035,
      "duration": 1880,
      "roads": [{
        "name": "판교역로241번길",
        "distance": 186,
        "duration": 47,
        "traffic_speed": 14.0,
        "traffic_state": 2,
        "vertexes": [127.1076, 37.4024, 127.1064, 37.4032]
      }],
      "guides": [{
        "name": "경유지",
        "x": 127.1735, "y": 37.3670,
        "distance": 596, "duration": 104,
        "type": 1000,
        "guidance": "경유지",
        "road_index": -1
      }]
    }]
  }]
}
```

**중요 1**: `vertexes`는 `[lng, lat, lng, lat, ...]` 형태의 **1차원 평탄 배열**이다. 폴리라인으로 그리려면 2개씩 끊어야 한다.

```js
const toLatLngs = (vertexes) => {
  const out = [];
  for (let i = 0; i < vertexes.length; i += 2) {
    out.push({ lng: vertexes[i], lat: vertexes[i + 1] });
  }
  return out;
};
```

**중요 2**: 경유지가 있으면 `sections`가 경유지 개수 + 1개로 쪼개진다. 전체 경로를 그리려면 모든 section의 모든 road의 vertexes를 순서대로 이어붙여야 한다.

**중요 3**: `routes[0].result_code !== 0` 이거나 `routes`가 비어 있으면 경로 없음이다. HTTP 200이어도 실패일 수 있으니 반드시 검사하라.

### 6.3 다중 목적지 길찾기 — 동선 최적화 전용

```
GET https://apis-navi.kakaomobility.com/guide/navi-api/destinations
```

> ⚠️ 위 URL은 **문서 페이지 경로**다. 실제 호출 엔드포인트 URL과 파라미터 형식은 확인하지 못했다. 구현 전 문서에서 확정하라.

**확인된 사실**: 하나의 출발지에서 한 개 이상의 다중 목적지까지의 **경로 요약 정보**를 제공한다. 최대 30개 목적지.

**오해 주의**: 이 API는 목적지들을 순회하는 경로를 짜주지 않는다. A→B, A→C, A→D 각각의 거리·시간을 한 번에 돌려주는 **1:N 비용 조회**다. 카카오모빌리티가 드는 대표 용도가 여러 위치의 택시 중 최적 배차를 고르는 것인 걸 보면 성격이 분명하다. 순서 결정은 §8처럼 로컬에서 해야 한다.

**카카오에는 공개된 경유지 순서 최적화 API가 없다.** TMS라는 배송 최적화 제품이 별도로 있으나 접근 조건이 다르다. 순서 최적화 API를 찾아 헤매지 마라.

### 6.4 주소로 좌표 변환

```
GET https://dapi.kakao.com/v2/local/search/address.json?query={주소}
```

응답 `documents[].x`(경도), `documents[].y`(위도). 지번·도로명 주소 체계를 모두 지원한다.

### 6.5 좌표로 주소 변환

```
GET https://dapi.kakao.com/v2/local/geo/coord2address.json?x={경도}&y={위도}
```

## 7. 딥링크 (카카오맵 URL Scheme)

대중교통·도보 안내와 실제 길 안내를 담당한다. **API 호출 0건, 쿼터 소모 없음.**

```
kakaomap://route?sp={출발위도},{출발경도}&ep={도착위도},{도착경도}&by={이동수단}
```

**좌표 순서가 REST API와 반대다.** REST는 `경도,위도`인데 URL Scheme은 `위도,경도`다. 이걸 틀리면 엉뚱한 곳이 뜬다.

| 항목 | 값 |
|---|---|
| `by` | `car` / `publictransit` / `foot` / `bicycle` |
| 경유지 | `vp`, `vp2`, ... `vp5` — 최대 5개 |
| 제약 | **대중교통은 경유지 설정을 지원하지 않는다** |
| 미설치 시 | `kakaomap://` 스킴을 인식하지 못하면 앱스토어 카카오맵 페이지로 연결 |
| 웹 폴백 | `http://m.map.kakao.com/scheme/route?...` (동일 파라미터) |

RN에서는 `Linking.openURL()`로 호출하고, `Linking.canOpenURL()`로 설치 여부를 먼저 확인해 폴백을 태워라. Android는 `AndroidManifest.xml`의 `<queries>`에 스킴 선언이 필요할 수 있다.

**⚠️ §10.3의 알려진 이슈를 반드시 먼저 읽어라.** `by` 파라미터가 무시된다는 보고가 있다.

## 8. 동선 최적화 설계

### 8.1 원칙 — TSP 라이브러리를 쓰지 마라

외근 방문지는 하루 3~6곳이다. 사무실을 고정 출발점으로 두면 순열 수는 n=5에서 120, n=6에서 720, n=8이라도 40,320이다. **자바스크립트 완전탐색으로 밀리초 단위에 끝난다.** 휴리스틱, 유전 알고리즘, 외부 라이브러리 전부 불필요하다.

```js
const permute = (arr) =>
  arr.length <= 1 ? [arr] :
  arr.flatMap((v, i) =>
    permute([...arr.slice(0, i), ...arr.slice(i + 1)]).map(p => [v, ...p]));

const optimize = (office, stops, cost) =>
  permute(stops)
    .map(order => ({
      order,
      total: [office, ...order].reduce(
        (sum, cur, i, a) => i === 0 ? 0 : sum + cost(a[i - 1], cur), 0)
    }))
    .reduce((a, b) => a.total <= b.total ? a : b);
```

방문지가 9곳 이상 들어올 여지가 있으면 그때 2-opt를 얹어라. 미리 만들지 마라.

### 8.2 두 가지 구현 단계

**1단계 (기본)** — 직선거리(Haversine)로 순서를 정하고, 확정된 순서로 자동차 길찾기를 **1회** 호출해 실제 경로를 그린다. API 1건. 같은 시·군·구 안에서 도는 외근이면 실제 최적과 거의 일치한다.

**2단계 (정확)** — 다중 목적지로 실제 소요시간 행렬을 만들고 완전탐색한다. 지점 6개(사무실+방문지 5)면 각 지점을 출발지로 6회 호출해 행렬을 채우고, 확정된 순서로 경로를 1회 더 그린다. 강 건너편처럼 직선거리가 배신하는 케이스를 잡는다.

**1단계를 먼저 완성하고 2단계를 얹어라.** 1단계만으로도 데모는 성립한다.

### 8.3 순서 고정 핀 — 이게 실제로 더 중요하다

현실의 외근에는 시간 제약이 있다. 민원인과 2시 약속, 기관 점심시간 회피, 오후 5시 이전 방문 같은 것들이다. 시간창이 들어간 TSP는 진짜로 어려운 문제다.

그런데 **UI에서 "이 방문지는 순서 고정" 핀을 제공하면 알고리즘은 더 쉬워지고 도구는 더 쓸모 있어진다.** 고정된 지점은 순열 대상에서 빠지므로 탐색 공간이 줄고, 사용자는 실제 업무 제약을 표현할 수 있다. 순수 최적화보다 이쪽을 먼저 구현하라.

### 8.4 경유지 5개 제약

자동차 길찾기의 경유지는 최대 5개다. 즉 사무실 + 방문지 6곳(경유지 5 + 목적지 1)까지가 한 번의 호출로 그릴 수 있는 한계다. 그 이상이면 구간을 나눠 여러 번 호출하거나 다중 경유지 API(최대 30개)를 도입해야 한다. **UI에서 하루 방문지를 6곳으로 제한하는 게 가장 간단한 해법이다.** 외근 실무상으로도 합리적인 상한이다.

## 9. React Native 통합

### 9.1 먼저 확인할 것

카카오맵을 RN에서 띄우는 방식은 두 가지이고, 폴리라인 그리는 방법이 완전히 다르다. **기존 코드베이스가 어느 쪽인지 확인하고 나서 작업하라.**

| 방식 | 판별 단서 | 폴리라인 방법 |
|---|---|---|
| WebView + JavaScript SDK | `react-native-webview` 의존성, `dapi.kakao.com/v2/maps/sdk.js` 스크립트 태그 | WebView 내부에서 `kakao.maps.Polyline` 생성. RN → WebView는 `injectJavaScript`, WebView → RN은 `postMessage` |
| 네이티브 SDK 브리지 | `apis.map.kakao.com` Android/iOS SDK 연동, 네이티브 모듈 코드 존재 | 네이티브 모듈이 노출한 메서드로 좌표 배열 전달 |

### 9.2 데이터 흐름

채택한 API는 **전부 REST**다. 네이티브 모듈이 필요 없고 JS 레이어의 `fetch`로 끝난다. 이게 이 스택의 가장 큰 장점이다.

```
[RN JS] 방문지 주소 입력
   → 주소로 좌표 변환 (dapi)
   → 동선 최적화 (로컬 완전탐색, 필요 시 다중 목적지로 행렬)
   → 자동차 길찾기 1회 (apis-navi)
   → 좌표 배열 정규화
[지도 레이어] 폴리라인 렌더
[딥링크] 안내 시작 / 대중교통·도보
```

지도 표시(SDK)와 경로 계산(REST)이 완전히 분리되어 있다. 이 경계를 흐리지 마라.

### 9.3 키 관리

REST API 키를 클라이언트 번들에 넣으면 추출된다.

- `.env` + `react-native-config`로 분리하고 저장소에 커밋하지 않는다
- 저장소가 공개라면 **반드시** 프록시 서버를 두고 키를 서버에만 둔다
- 키가 노출되면 남의 호출로 쿼터가 소진된다

## 10. 알려진 이슈 (2026-08 기준)

### 10.1 대중교통 경로 API의 미해결 오류 — 채택 제외의 근거

이 API는 채택하지 않았으나, 나중에 도입을 검토할 경우를 위해 남긴다.

- `{ "errorType": "BadRequest", "message": "API limit has been exceeded.", "code": -10 }` 가 HTTP 400으로 반환됨. 무료 쿼터 배지가 있고 실제 사용량이 수십 건인 상태에서도 발생한 사례가 복수 보고됨
- `"sx is required"` 오류가 파라미터를 명백히 포함한 요청에서도 발생
- 같은 앱의 같은 키로 로컬 API는 정상 동작. 대중교통 경로만 실패
- 권한 프로비저닝 문제로 추정되며 코드 수정으로 해결되지 않음. 데브톡 문의 필요

### 10.2 대중교통 응답의 도보 구간

전체 경로가 `출발지 - 도보 - 대중교통 - 도보 - 목적지` 구조인데, 승하차 정류장까지의 도보 구간 처리에 대한 문의가 접수된 상태다. 딥링크 전환으로 이 문제도 함께 회피된다.

### 10.3 URL Scheme의 `by` 파라미터가 무시됨 — 확인 필수

**딥링크가 대중교통·도보를 담당하므로 이 이슈는 이 프로젝트에 직접 영향이 있다.**

`by` 파라미터를 `publictransit`이나 `foot`으로 지정해도 카카오맵이 항상 자동차로 열린다는 보고가 있다. 2023년 5월 안드로이드 스킴에서 처음 제기됐고, 2026년 5월에도 모바일웹 스킴(`m.map.kakao.com/scheme/route`)에서 동일 증상이 보고됐다. 3년 넘게 미해결 상태로 보인다.

**대응**: 구현 초기에 실기기에서 `by=publictransit`을 테스트하라. 작동하지 않으면 목적지만 전달하는 스킴으로 폴백하고, 사용자가 카카오맵 안에서 이동수단을 직접 고르게 하라. 기능적 손실은 탭 하나다.

### 10.4 대응 원칙

- 경로 조회 실패 시 앱이 죽지 않고 "경로를 불러올 수 없습니다 + 카카오맵으로 열기" 폴백으로 빠지게 하라
- 응답 헤더의 `x-request-id`를 반드시 로깅하라. 데브톡 문의 시 필요하다
- 개발 초기에 실제 응답 JSON을 파일로 덤프해 두면 API가 죽어도 목 데이터로 UI 개발을 계속할 수 있다

## 11. 쿼터 소진 방지

채택 API 중 **다중 목적지(일 1,000건)만 관리 대상**이다. 나머지는 여유가 크다.

1. **행렬 캐싱** — 좌표를 소수점 4자리로 반올림해 캐시 키를 만든다. 같은 방문지 조합의 재조회를 막는다. TTL 30분 이상으로 잡아도 무방하다
2. **명시적 트리거** — 방문지 추가/삭제 시마다 자동 재최적화하지 마라. "동선 최적화" 버튼으로만 호출한다
3. **1단계 우선** — 직선거리 최적화(§8.2)를 기본값으로 두고, 사용자가 "정확한 소요시간으로 다시 계산"을 눌렀을 때만 다중 목적지를 호출한다. 이것만으로 호출량이 한 자릿수로 떨어진다
4. **개발용 목 모드** — `USE_MOCK_ROUTE=true` 플래그로 저장된 JSON을 반환하게 한다
5. **쿼터 모니터링** — 앱 관리 페이지 [통계] > [쿼터]. 시연 전날 확인하라

## 12. 미검증 항목 — 사실로 가정하지 말 것

1. **다중 목적지 길찾기의 실제 호출 엔드포인트 URL, 요청 파라미터, 응답 스키마.** 문서 페이지 경로만 확보했다
2. **다중 목적지의 쿼터 카운트 방식.** 1회 호출이 1건인지, 목적지 개수만큼 차감되는지 불명. 후자라면 최적화 1회에 최대 30건이 나간다. **구현 전 소량 호출로 실측하라**
3. **자동차 길찾기의 rate limit(초당 호출 수).** 일간 쿼터와 별개로 존재하는지 미확인
4. **응답 데이터의 캐싱·저장 허용 범위.** 카카오 API 결과를 로컬 DB에 저장하는 것이 약관상 허용되는지. 캐싱 설계 전 [서비스 약관](https://developers.kakao.com/terms/latest/ko/site-terms)과 [운영 정책](https://developers.kakao.com/terms/latest/ko/site-policies)을 확인할 것
5. **카카오맵 로고 표기 의무.** [도구] > [리소스 다운로드] > [카카오맵]에서 로고와 디자인 가이드를 제공하며 준수를 "권장"한다고만 되어 있다. 의무인지 불명확하나 표기해 두는 편이 안전하다
6. **URL Scheme의 Android `<queries>` 선언 필요 여부.** Android 11+ 패키지 가시성 정책 관련

## 13. 권장 구현 순서

1. 앱 생성 → 카카오맵 활성화 → 무료 쿼터 배지 확인
2. **주소로 좌표 변환**부터 붙인다. 방문지 등록 플로우의 기반이다
3. **자동차 길찾기 단일 구간**(경유지 없이 A→B)으로 폴리라인 렌더 파이프라인을 완성한다. 가장 안정적이고 문서화가 잘 되어 있다
4. **경유지를 추가**해 다구간 경로를 그린다. `sections` 이어붙이기를 여기서 처리한다
5. **직선거리 기반 동선 최적화**(§8.2 1단계)를 얹는다. 여기까지가 핵심 데모다
6. **딥링크**를 붙인다. §10.3의 `by` 파라미터를 실기기에서 즉시 검증한다
7. 여유가 있으면 좌표로 주소 변환, 순서 고정 핀, 다중 목적지 기반 정확 최적화 순으로 확장한다

**3~5번까지만 완성해도 발표는 성립한다.** 6번 이후는 여유분으로 취급하라.

## 15. 검토하지 않은 대안

카카오 단일 스택 결정을 뒤집을 사유가 생겼을 때만 열어보라.

- **TMAP** — 국내 유일하게 **경유지 순서 최적화 API**를 공개 제공한다(경유지 최적화 10/20/30/100). 다만 무료 등급 제공량이 최적화 10·20은 일 50건, 30·100은 일 1건이라 실용성이 낮다. 일반 경로안내도 일 1,000건이며 인앱 내비게이션은 별도 계약이 필요하다
- **네이버 클라우드 Maps** — Dynamic Map 월 600만 건, Directions 5 월 6만 건 무료. RN 라이브러리(`@mj-studio/react-native-naver-map`) 성숙도가 높다. Directions는 자동차 전용이라 대중교통이 빠진다
- **ODsay** — 대중교통 전문. Basic 등급이 개인·학생·5인 이하 스타트업 한정 일 1,000건이며 **앱 등록 후 6개월만 무료**다. 학생 팀은 자격에 해당하나 시한이 있다
- **구글 지도** — 2026년 2월 고정밀 지도 국외 반출이 조건부 허가됐으나, 조사 기준일 현재 국내 자동차·도보 길찾기는 여전히 미제공이다. 현 시점 선택지가 아니다
