### [B-2] login/signup 성공 시 `user: undefined` 들어갈 수 있는 회로
- **위치**: [src/stores/authStore.ts:181, 209](../src/stores/authStore.ts#L181)
- **재현/근거**: 백엔드가 (의도치 않게) login/signup 응답에서 user 필드를 빠뜨릴 경우. refresh 처럼 백엔드 contract 가 흔들렸을 때 회복력 부족.
- **현재 동작**: `set({ user: session.user, ... })` — `isValidSession` 가드가 user 를 옵셔널로 허용하므로 user 가 빠진 응답이 와도 `isValidSession` 통과 → `state.user = undefined` 로 들어감 (zustand partial set). 화면들은 `s.user?.name` 식으로 옵셔널 체이닝 쓰고 있어 즉시 깨지진 않지만, `user: User | null` 타입과 어긋남.
- **기대/제안**: hydrate 가 이미 쓰는 `session.user ?? null` 패턴으로 통일. login/signup 도 user 가 없으면 `auth.me()` 백그라운드 보강 또는 명시적 에러 처리.
- **영향도**: low (현재 백엔드는 user 동봉). 타입·정책 일관성 위해 정리 권장.
