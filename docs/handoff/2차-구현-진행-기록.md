## 4. 서버 실측 (2026-10-17, 운영)
- `/storage/...` 기존 사진 파일 전부 404(유실 추정). 새 업로드는 200. 응답에 Content-Type 없음 (백로그 E)
- 체크인은 멱등이 아님: 같은 외근·현장으로 두 번 보내면 방문 2건. 앱은 다시 보내기 전에 외근 timeline으로 확인한다 (백로그 H, clientId 요청)
- 외근 `?force=true` 삭제: 보고서·현장이 남음 (C)
- 현장 `?force=true` 삭제: 방문·목적지가 남음. 진행 중 외근 목적지인 현장은 force 없이 삭제됨 (F)
- 분류 rename/delete가 현장에 반영되지 않음. 현장 PATCH의 `projectId: null`, `jibunAddress`는 동작함(OpenAPI 미기재) (G)
- 현장 이름을 `""`로 PATCH하면 무시됨 → 앱이 주소를 이름으로 보냄

백로그 `docs/backend/backend-backlog.md` '2차 개편 요청' A~J:
- A: 비밀번호 찾기
- B: 보고서 상태·출발 좌표
- C: 외근 삭제 범위
- D: 방문 조치 상태
- E: 사진 404
- F: 현장 삭제 범위
- G: 분류 cascade
- H: 체크인 visitedAt·tripId·clientId
- I: HWPX
- J: 사진 일괄 등록
